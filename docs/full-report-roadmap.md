# 로드맵 — MD 일체 → 무편집 제출본 (궁극 목표)

**목표:** 연구자가 모든 사전 내용을 Markdown으로 쓰면, `hwp-agent`가 기관 양식에
채워 **손대지 않고 과제 접수 담당자에게 보낼 수준의 한글 최종보고서**를 낸다.

**현재 도달점(2026-08-21):** 미래기획 최종보고서 본문 MD 9개(2,675줄) → 전략과제
양식에 `write` 한 번으로 **134페이지 조판**. 본문 프로즈·헤딩(Ⅰ./1./1))·중첩 불릿
(■→•)·인라인 표기가 **양식 스타일 그대로** = 사실상 제출 품질. 남은 것은 표·그림·
표지·목차·머리말. 검증 기준(gold standard) = 수동 최종본
`…260821_편집_인용반영.hwpx`.

---

## 아키텍처: "report build" 파이프라인

MD 여러 조각 + 메타데이터 + 에셋을 양식에 조립하고, 상호참조·번호를 해석하며,
목차는 한글 자동필드로 주입하는 **단일 빌드 명령**(`hwp-agent build report.toml`).
입력은 MD, 출력은 제출본 하나.

### 백본 — 상호참조·번호 엔진 (모든 Phase가 의존)
- **장(章) 범위 번호:** 표/그림에 소속 장(HEADING_1) 기준 번호 부여 → `표 Ⅲ-1`, `그림 Ⅳ-2`.
- **앵커·참조:** MD 표/그림에 앵커(`{#tbl_as_is_systems}`), 인라인 `{ref:tbl_as_is_systems}` → `표 Ⅲ-1` 로 해석.
- **캡션 생성:** 표/그림마다 양식 스타일 캡션(`<표 Ⅲ-1> …`, `[그림 Ⅳ-2] …`) + 주/자료 줄(`_NOTE_RE` 활용).
- 이 엔진이 표·그림·목차(표차례·그림차례)를 모두 먹인다. **먼저 만든다.**

## Phase 0 — 다중 섹션 조립 (기반)
지금 `write`는 `{{body}}` 한 곳만 채운다. 최종보고서는 요약·들어가며·본문·참고문헌이
**서로 다른 섹션**(각자 머리말·쪽날개).
- 마커 확장: `{{summary}}`·`{{intro}}`·`{{body}}`·`{{references}}`(+기존 `{{appendix}}`).
- config(`overrides/<form>.json`)가 마커→섹션 선언(요약2·들어가며3·본문4·참고문헌5).
- 빌드 매니페스트: MD 파일→마커 매핑(00_요약→summary, 들어가며→intro, 01–08→body, 09→references).
- `ops/author.py` `INSERTION_MARKERS` 확장 + 섹션별 삽입.

## Phase 1 — 표지·판권 슬롯 + 메타데이터 (빠른 성과)
- config가 표지·판권 슬롯맵 선언(예시 텍스트→`{{title}}`·`{{report_number}}`·`{{lead_researcher}}`·`{{pub_date}}`·`{{isbn}}`…). 골든템플릿(`정책과제-template.hwpx`)에 이미 검증된 패턴.
- 메타 소스: MD 프론트매터 또는 `meta.json`(제목·저자·발행일…).
- 파이프라인: bake(표지·판권 슬롯화) + 기존 `form fill`(메타 채움). **기존 기능 조합.**

## Phase 2 — 표
MD에 markdown 파이프표가 **이미 존재** → `write`가 조판함. 갭은 (a)집·(b)번호·(c)참조·(d)주.
- **집(house style):** strip 시 본문 섹션의 표 하나를 중립화해 `{{table_template}}`로 남긴다(현재는 표까지 제거 → 서식참조 없음). strip에 "표 1개 보존" 옵션.
- **번호·캡션·참조:** 백본 엔진으로 `{#tbl_X}`→번호, `{ref:tbl_X}` 인라인 해석, 캡션 생성.
- **주/출처(사용자 지적 2026-08-21):** 기관 양식은 표의 **맨 아래 행을 병합(1 row full-span)** 하고 **전용 스타일**로 주/출처를 넣는다. 현재는 표 바로 아래에 **그냥 텍스트**로 붙음 → 틀림. `주)`/`자료)`/`출처)` 줄을 감지해 **표의 마지막 셀행에 병합 행으로 편입** + 주석 스타일. **이중화 박사 버전이 이 처리를 잘 하므로 참고**(그 산출물/로직 확보해 대조). 표 작업 착수 시 이 항목부터 규약 확정.

## Phase 3 — 그림
- MD 그림 문법 `![alt](assets/x.png){#fig_X}` → `write`가 이미지 임베드(기존 `ops/image` BinData 삽입 재사용) + 캡션 `[그림 Ⅳ-2]` + 양식 그림 스타일.
- 번호·참조는 백본 공유. 에셋은 보고서 `assets/`에서.

## Phase 4 — 목차/차례 (난관 1)
페이지 번호는 조판(레이아웃) 후에만 정해짐 → **우리가 계산하지 않는다.**
- **한글 자동 차례 필드 주입:** 목차 섹션에 `차례`·`표차례`·`그림차례` **필드 컨트롤**(`<hp:ctrl>`)을 넣어, 한글이 열 때(F5/필드 갱신) 스스로 항목·페이지번호를 채우게 한다. HWPX 차례 필드 마크업 조사 필요.
- **폴백:** 필드 주입이 어려우면, 헤딩에서 정적 차례를 생성하되 페이지번호는 자리표시 + "한글에서 갱신" 안내(=키 한 번). 무편집엔 못 미치지만 근접.

## Phase 5 — 머리말/쪽날개 (난관 2)
양식은 마스터페이지 12개에 장별 머리말(예: "Ⅰ.세계경제전망"). ctrl+autoNum 존재 → **필드성일 가능성**.
- **조사 먼저:** 머리말이 HEADING_1을 참조하는 필드면 실제 헤딩만 들어가면 자동 갱신(최상). 정적이면 섹션별 마스터페이지 머리말 텍스트=장 제목으로 설정(장별 작업).
- 가장 어려워 **마지막**.

## 순서와 근거
0. **백본(상호참조·번호) + Phase 0(조립)** — 나머지 전부의 전제.
1. **Phase 1(표지·판권)** — 기존 form-fill 조합, 문서 식별 가능해지는 빠른 성과.
2. **Phase 2(표)** — 데이터가 이미 MD에 있어 가성비 높음.
3. **Phase 3(그림)** — 표와 같은 엔진.
4. **Phase 4(목차)** — 헤딩·표·그림이 있어야 차례가 성립 → 그 뒤.
5. **Phase 5(머리말)** — 레이아웃 의존·최난관 → 마지막.

## 리스크·현실
- **목차 페이지번호·장별 머리말은 한글 레이아웃 의존** → 우리 계산이 아니라 **한글 자동필드 주입**이 정공법. 필드 주입이 HWPX에서 불가하면 이 둘만 "한글에서 F5" 한 번 남는다(사실상 무편집).
- `write` 출력은 python-hwpx 재저장(재압축)을 거침 → 컨테이너/보안 청결 유지 확인 필요.
- 각 Phase 끝에 **답안지(`…_편집_인용반영.hwpx`)와 렌더 비교**로 회귀·근접도 측정.

## 한 줄 요약
백본(번호·참조) → 조립(다중 섹션) → 표지·표·그림(기존 기능 확장) → 목차·머리말
(한글 자동필드). 본문은 이미 도달; 표·그림·표지는 로드맵이 뚜렷; 목차·머리말이 마지막 벽.

# 실행 상세 — A → B → C (착수 순서)

> **발견(2026-08-21): A2(상호참조·번호)는 이미 구현돼 있음.** `ops/author.py`의
> `_resolve_cross_refs`가 표 캡션 `{label:id}` 등록 → `{ref:id}`를 `표 {장}-{N}`으로
> 치환(장-범위 번호, `{{chapter_number}}`, 캡션 프레이밍 `<표 …>`/`[그림 …]` 파싱까지).
> 미래기획 MD가 **정확히 이 문법**(`{label:tbl_as_is_systems}`·`{ref:…}`·`자료)`)을 씀.
> → **A2 남은 일 = 그림으로 확장뿐.** C(표)도 대폭 축소: (1)table_template 보존
> (2)주/출처 병합행. 표 자체 조판·번호·참조는 이미 됨(134p 실증에서 표 블록도 배치됨).

## A. 다중 섹션 조립 (+ 그림 번호 확장)
전제 계층. A2는 표에 대해 완료 — A1(조립)이 실질 과제.

- **A1. 다중 섹션 마커·조립**
  - `ops/author.py` `INSERTION_MARKERS`에 `{{summary}}`·`{{intro}}`·`{{references}}` 추가(기존 body/appendix 유지). 각 마커는 채워지면 소비.
  - bake(굽기)에서 config `sections`(예 `{"summary":2,"intro":3,"body":4,"references":5}`)대로 **해당 섹션을 strip + 해당 마커 삽입**(현재 body 전용 → 일반화).
  - 조립 매니페스트(TOML/JSON): `{marker: md파일}`. 신규 `hwp-agent build <manifest>` 또는 `write --part summary=00_요약.md --part body=01_..08.md …`. 각 파트를 제 마커에 배치.
  - 검증: 미래기획 요약/들어가며/본문/참고문헌을 각 섹션에 배치 → 렌더로 섹션별 머리말·쪽날개 정상 확인.
- **A2. 상호참조·번호 엔진** (`ops/crossref.py` 신규 또는 author 내)
  - 블록 파싱 때 표/그림 앵커(`{#tbl_X}`/`{#fig_X}`) 수집, **현재 장(HEADING_1=로마자) 기준** 장-범위 카운터로 번호 부여(`표 Ⅲ-1`·`그림 Ⅳ-2`).
  - ref-map 구성 후 인라인 `{ref:tbl_X}`→라벨 치환(2-pass: 1차 수집, 2차 치환).
  - 캡션 문자열 생성 규약(`<표 Ⅲ-1> 제목` / `[그림 Ⅳ-2] 제목`)도 여기서.
  - 표·그림·목차가 공유. **먼저 세운다.**

## B. 표지·판권 슬롯 + 메타데이터
- **B1. 슬롯화**: bake config `cover`/`colophon` 슬롯맵(예시 문자열→`{{title}}`·`{{report_number}}`·`{{lead_researcher}}`·`{{pub_date}}`·`{{isbn}}`…). `정책과제-template.hwpx`의 검증된 매핑을 config로 이식(문자열 매칭은 서식별이라 override처럼 per-form).
- **B2. 메타 채움**: `meta.json`(또는 MD 프론트매터)→기존 `form fill`. 파이프라인 `build`가 write(본문)+form fill(메타) 순차.
- 검증: 표지에 실제 제목·연구진, 판권에 발행정보 → 답안지 표지/판권과 대조.

## C. 표 (주/출처 규약 포함)
- **C0. 이중화 박사 표 처리 확보**: 그의 산출물/변환 로직에서 "주/출처=병합 하단행+전용스타일" 처리 방식을 확보해 규약 확정(착수 전 선행).
- **C1. table_template 보존**: 본문 strip을 "표 1개는 중립화(`{{table_template}}` 캡션)해 남김"으로 조정.
- **C2. 표 조판**: markdown 파이프표를 table_template 서식으로 조판(기존 write 표 기능) + 캡션·번호(백본).
- **C3. 주/출처 병합행**: 표 아래 `주)`/`자료)`/`출처)` 줄을 **표 마지막 행에 full-span 병합 셀**로 편입 + 주석 스타일(현재 텍스트 배치 → 교체).
- **C4. 참조**: `{ref:tbl_X}` 해석(백본).
- 검증: 답안지의 표(캡션·번호·주 병합행)와 픽셀 근접 대조.

- 착수: **A1 → A2 → B → C** 순. A1부터 코드.
