# 출력 덮어쓰기 가드 (overwrite-guard) — 제안

## 배경 / 문제

`write` / `form fill` / `image replace` 등은 `-o/--output` 경로(또는 in-place `--file`)에
결과를 **무조건 새로 쓴다.** 그 출력 파일이 *이전 hwp-agent 출력 이후 외부(한글)에서
사용자가 수정한 것인지*를 전혀 확인하지 않는다. 코드도 이 빈틈을 인정하고 있다:

> `src/hwp_agent/cli/main.py` — *"output paths are never checked — they're created."*

실제 사고: 사용자가 hwp-agent가 만든 HWPX를 받아 한글에서 그림 1·2·3을 일일이
삽입·저장 → 이후 본문 용어 변경을 위해 **같은 파일명으로 재생성** → 사용자의 그림
삽입 작업이 통째로 덮어써짐(자동복구·스냅샷 없어 복구 불가).

## 목표

- 버전 파일명(`_v2`, `_v3`)은 **지저분**하므로 쓰지 않는다.
- **최소 비용**으로 "외부에서 수정된 출력 파일을 말없이 덮어쓰는 것"만 막는다.

## 설계: provenance 지문(fingerprint)

출력 시 그 파일의 `sha256`을 기록해 두고, 다음 번 덮어쓰기 직전에 현재 파일 해시와 비교.

**기록 위치 (택1)**
1. **사이드카** `.<name>.hwpagent.json` — `{ sha256, tool_version, written_at }`.
   가장 단순. 단점: 파일이 하나 더 생김(숨김 처리).
2. **HWPX 내부 메타/파트** — 클러터 없음. 단, 자기 자신을 포함한 해시가 되지 않도록
   "지문 파트를 **제외한** 나머지 파트의 해시"로 정의해야 함(self-hash 주의).

**덮어쓰기 직전 검사**
- 대상 파일 없음 → 그냥 쓴다(기존과 동일).
- 대상 있음 + 기록 지문 **없음**(= hwp-agent가 만든 게 아님) → **중단**.
- 대상 있음 + 기록 지문 **있고 현재 해시와 다름**(= 외부 수정됨) → **중단**.
- 대상 있음 + 기록 지문 == 현재 해시(= 내가 만든 그대로) → 조용히 덮어쓴다.

중단 시: 무엇이 감지됐는지 + 해결법(`--force`로 강제, 또는 다른 `-o` 지정)을 명확히 출력.

## CLI 표면

- `write` / `form fill` / `image replace` / `meta --set` 공통으로 `--force`(별칭 `--overwrite`).
  기본은 **거부**, `--force`로만 우회. (`convert` / `setup`에 이미 `--force` 전례 있음 → 일관.)

## 비용 / 호환성

- 비용: 해시 1회(`sha256`). `mtime + size` 1차 필터로 동일하면 해시 자체를 생략 가능.
- 호환: 신규 출력(대상 없음)엔 동작 영향 없음. **기존 파일을 덮어쓸 때만** 가드가 작동.
- MCP/서버 경로도 같은 검사를 공유하도록 단일 헬퍼(`guard_output(path) -> ok|reason`)로.

## 비고

- 이 기능의 본질은 "버전 테스트"가 아니라 **drift 감지**: 내가 마지막에 쓴 바이트와
  지금 디스크의 바이트가 다르면 = 누군가 손댐 = 말없이 덮지 말 것.
- 사용자 워크플로 맥락: 맥 한글 2014는 삽입 그림이 화면상 깨져 보여 PDF로 변환해
  확인 → 그림 삽입이 비싼 수작업이라, 출력 덮어쓰기 사고의 피해가 특히 큼.
